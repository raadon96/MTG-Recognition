### Secret Separation Pattern
**Source:** DVC design (no codebase analog, but critical rule)
**Apply to:** `.dvc/config` and `CONTRIBUTING.md`
- Public OAuth setting (`gdrive_client_id`): `dvc remote modify origin ...` → goes to `.dvc/config` (committed)
- Secret OAuth setting (`gdrive_client_secret`): `dvc remote modify --local origin ...` → goes to `.dvc/config.local` (gitignored)
- Never commit `gdrive_client_secret` — verify with `git diff --cached .dvc/config` before committing

## Migration Operations (Non-File Patterns)

This phase includes filesystem and git operations that are not file edits. The planner must sequence these correctly per RESEARCH.md Pattern 1.

**Safe sequence (ordered — each step depends on prior):**

1. Edit `pyproject.toml` → run `uv sync --dev` (installs DVC)
2. `dvc init` → commit `.dvc/` and `.dvcignore`
3. Create GCP OAuth app → configure `dvc remote add` and `dvc remote modify`
4. `mkdir -p data/test/6_benchmark` → `mv benchmarks/dataset/images data/test/6_benchmark/` → `mv benchmarks/dataset/ocr data/test/6_benchmark/`
5. `git rm -r --cached benchmarks/` → update `.gitignore` (replace benchmark lines with `benchmarks/`)
6. `dvc add data/test` → produces `data/test.dvc`
7. `dvc push` (triggers browser OAuth, uploads ~879+ files)
8. `git add pyproject.toml .gitignore .dvc/config data/test.dvc CONTRIBUTING.md` → commit

**Data loss safeguard (from D-04):** Files must be moved (step 4) before `git rm --cached` (step 5). If step 5 runs first and is interrupted, data is lost from git without existing elsewhere.
