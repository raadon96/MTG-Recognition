<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local repo -> git remote (GitHub) | `.dvc/config` will be pushed to a public-or-shared git remote — anything written here is effectively published to all repo readers |
| Local repo -> Google Drive API | `dvc push`/`pull` exchanges OAuth tokens with Google; cached at `~/.cache/pydrive2fs/` |
| Developer shell -> Claude executor | OAuth credentials passed via env vars; never logged to stdout |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `gdrive_client_secret` written to `.dvc/config` (committed) | mitigate | MUST use `dvc remote modify --local origin gdrive_client_secret "$GDRIVE_CLIENT_SECRET"` (Task 4 step 3). Acceptance criterion `grep -F 'gdrive_client_secret' .dvc/config` returns exit 1 enforces this. |
| T-01-02 | Information Disclosure | OAuth credentials echoed to terminal/logs via shell history or process listing | mitigate | Pass via env vars (`$GDRIVE_CLIENT_ID`, `$GDRIVE_CLIENT_SECRET`) populated by user export; never inline literals in command text. The `dvc remote modify` command takes the value via shell expansion only. |
| T-01-03 | Information Disclosure | `gdrive_client_id` committed to `.dvc/config` | accept | OAuth client_id is public by design — appears in OAuth flow URLs visible to end users. RESEARCH Open Question #2 confirms. Documented in CONTRIBUTING.md (Plan 03). |
| T-01-04 | Spoofing | Default DVC OAuth app blocked by Google ("This app is blocked") | mitigate | Custom GCP OAuth app required (RESEARCH Pitfall 1). Task 3 checkpoint enforces this — execution cannot continue without user-provided custom credentials. |
| T-01-05 | Tampering | `pyproject.toml` `dvc[gdrive]` line replaced/corrupted by drift in `uv sync` | accept | `uv.lock` pins exact resolved versions; `git diff pyproject.toml` acceptance check confirms only one expected line added. Low risk for a single-developer dependency edit. |
| T-01-06 | Information Disclosure | `~/.cache/pydrive2fs/<client_id>/default.json` cached OAuth token leak via shared system | accept | Token is per-user; cache directory is mode 0700 by default (pydrive2fs convention). Out-of-scope: machine-level access control. Documented in CONTRIBUTING.md so collaborators know where the token lives. |

**ASVS L1 mappings:**
- V2 Authentication: Custom OAuth app per developer (T-01-04) — V2.1.1 enforced by checkpoint.
- V14 Configuration: Secret separation via `.dvc/config.local` (T-01-01) — V14.1.5 (no secrets in source control) enforced by acceptance criteria.
</threat_model>
