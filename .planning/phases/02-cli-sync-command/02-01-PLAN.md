## Phase Goal

**As a** collaborator setting up the MTG Recognition project, **I want to** run a unified `mtg` CLI that exposes the existing recognition and segmentation pipelines as short subcommands, **so that** I can invoke any pipeline operation with `mtg <subcommand>` instead of long `python -m ...` paths — without breaking the existing module invocations.

## Plan 01: Vertical Slice — `mtg` Click Group + `recognize` and `segment` Subcommands

<objective>
Deliver the first usable vertical slice of the unified CLI: a `mtg` Click group declared as a console-script entry point in `pyproject.toml`, with `recognize` and `segment` subcommands wired via `Click.add_command()` so they inherit the existing options without duplication. After this plan, `mtg recognize -i ...` and `mtg segment -i ...` work end-to-end after a single `uv sync` — and the legacy `uv run python -m mtg_recognition.engine.pipeline` / `uv run python -m mtg_recognition.engine.segmentation.cli` invocations remain unchanged.

Purpose: Establish the CLI foundation other subcommands (`build-index`, `sync`) will attach to in later plans. Implements decisions D-11 (`add_command` reuse) and D-12 (flat `cli.py` module).

Output: New `src/mtg_recognition/cli.py` with the `cli` group, `[project.scripts]` block in `pyproject.toml`, and `tests/unit/test_cli.py` asserting subcommand registration via Click's `CliRunner`.
</objective>
